# niri desktop

- Config: `dotfiles/config/niri/config.kdl` (linked to `~/.config/niri/`). `niri validate` before saving; niri reloads on save.
- `environment {}` sets `CHROME_FLAGS` (Void's chromium wrapper reads only that, no flags file) and `ELECTRON_OZONE_PLATFORM_HINT`. Autostart: `spawn-at-startup` lines.
- Keys (bépo right hand, arrows also work): `Mod+T/S/R/N` = left/down/up/right, `Ctrl` moves, `Shift` changes screen. `Mod+Return` foot, `Mod+Space` menu, `Mod+D` app launcher, `Mod+Y` AI agent (`fili-ai`), `Super+Alt+L` lock. `Mod+K` lists them.
- Personal additions: `users/<login>/dotfiles/config/niri/local.kdl` (included at the end of `config.kdl`).
- Shell: **fili-shell**, one Quickshell process (replaces waybar, mako, fuzzel), config `dotfiles/config/quickshell/`. Use these names with the user:

  | Name | What | File |
  | --- | --- | --- |
  | fili-shell | the Quickshell process, and its client `~/.local/bin/fili-shell` | `shell.qml`, `FiliShell.qml` (commands) |
  | fili-bar | top bar, one per screen | `FiliBar.qml` (+ `BarScript`, `BarItem`, `BarHover`, `BarPower`) |
  | fili-tooltip | hover card of a bar module (details + click hints, Omarchy panels as model) | `FiliTooltip.qml`, data `FiliInfo.qml` (network/power/monitor from resident `bar-stats` over its stdin, `bar-stats info TOPIC` on the command line; displays from the niri socket), no process per hover |
  | fili-panel | action window under a bar module (click: network/Wi-Fi, sound, Bluetooth, power, monitor; card-sized layer window, not full screen: 32 MB less while open; Esc, a click on a window (focus lost) or on the bar closes; keyboard: Mod+A opens the last panel or closes, ←/→ next panel in bar order incl. the notification center (Shift+←/→ on a slider, a choice row or a text field), ↑/↓ or Tab between items (`FocusRing` outline), Enter/Space acts, Shift+Enter = right click; `fili-shell panel NAME` for a key) | `FiliPanel.qml`, views `Panel*.qml`, scripts `fili-net` (iwctl), `fili-speedtest` |
  | fili-ai (bar module) | AI agent icon: grey without session, count of sessions, `ASK` (sand, blinking) when a session waits for a permission or an answer, `DONE` when a turn ended unwatched; card: each session (window title, state, context %, cost, model) and the plan's 5-hour/weekly limits as gauges (tick = steady pace: elapsed part of the window; a card row `[label, value, {value, mark}]` draws one); click: the waiting session's niri window (else the latest, again: the next), none: starts fili-ai like Mod+Y; middle: new session; right: choose the agent. Fed by Claude Code hooks and its status line (`~/.claude/settings.json`: `fili-ai-session hook` / `statusline`, which also prints the status line), never its credentials; notification on a wait unless the window is focused. Claude Code only (Codex/opencode: click still launches them) | `BarState.qml` (`aiFor`), `apps/fili-ai-session` (Rust, ~1 ms per event, niri socket direct; state in `$XDG_RUNTIME_DIR/fili-ai/state.json`) |
  | fili-calendar | month grid under the clock | `FiliCalendar.qml` |
  | fili-notification | notification bubbles (top right) | `FiliNotification.qml` |
  | fili-notification-center | notification history panel (bell icon) | `FiliNotification.qml` |
  | fili-launcher | fuzzy picker used by `menu`, the timer, `fili-ai`; blurred backdrop (layer `fili-launcher`) | `FiliLauncher.qml` |
  | fili-about | "About" window (logo, Filigrane version, OS, machine), centred; `fili-shell about`, menu System › About, middle click on the bar logo; C copies it as text | `FiliAbout.qml`, data `fili-about` (JSON, run on open only) |
  | fili-theme | colours and fonts (brand.md) | `FiliTheme.qml` |
  | fili-i18n | translations: English in the code (`FiliI18n.tr("...")`), catalog `i18n/<lang>.json` shared with bar-stats; language from `FILI_LANG`, then the user's choice, then `LC_ALL`/`LC_MESSAGES`/`LANG` (`C` = English); scripts use `lib/i18n.sh`; check with `scripts/check-i18n.sh` | `FiliI18n.qml`, `i18n/fr.json` |
  | fili-lang | switch the session language live: `fili-lang set fr\|en\|system` (keyboard panel LANGUAGE, menu › System › Language); state `~/.local/state/filigrane/locale`, `LANG` for new apps in `~/.config/niri/locale.kdl`; glibc locales from `LOCALES` in `config.env` (bootstrap.sh) | `~/.local/bin/fili-lang` |

  Software rendering (`QT_QUICK_BACKEND=software` pragma in `shell.qml`, no GL context: about half the memory). Tests: `tests/fili-shell/run.sh` (isolated Quickshell instance on a private D-Bus, real config, windows hidden, clicks recorded instead of run: every fili-bar click, the fili-shell channel, fili-launcher, fili-notification, fili-tooltip, FiliInfo; TAP output, exit 0 when all pass). `tests/fili-shell/ci.sh` runs the same tests without a desktop (headless sway + nested niri, used by the CI). Run it after any change to `dotfiles/config/quickshell/` or the `bar-*`/`fili-*` scripts; a new module gets an `objectName` and an `expectClick` line in `tests/fili-shell/TestShell.qml`. Client commands (named pipe `$XDG_RUNTIME_DIR/fili-shell`, no Qt client): `fili-shell bar refresh N` (was `pkill -RTMIN+N waybar`), `fili-shell notification dnd on|off|toggle|dismiss-all|dismiss TEXT|center|history`, `fili-shell panel network|audio|bluetooth|power|monitor|close`, `fili-shell launcher [fuzzel --dmenu options]`, `fili-shell launcher close`, `fili-shell about`, `fili-shell reload`. Logs: `/run/user/$UID/quickshell/`.
- Menu: `~/.local/bin/menu` (fili-launcher via `fili-shell launcher`, one fuzzy list: `~/.config/menu/entries`, .desktop apps, "Category: Action" entries; `menu <section>` jumps to clip, emoji, calc...). `Shift+BackSpace` up one level, `Escape` quits.
- fili-tooltip / fili-panel info standard: every card is `{ title, rows: [[label, value]...] | text, hint }` and is laid out with the **title on the left, the content on the right** (rows: grey label, white value; optional gauge), then a separator and the click hint. A script tooltip in plain text gets its title from `BarScript { title: ... }` (or its `tag`); `PanelInfo { title: true }` follows the same layout. Never a bare one-line string for a new module. Wheel on any bar module is accumulated (120 = one notch) in `BarHover`, so a touchpad does not fire one action per event; volume and brightness step 3 %.
- fili-bar modules: modules are `{text, class, tooltip}` objects (waybar custom JSON protocol, `BarScript.qml`): from a script (`cmd`: `bar-status`, `bar-news`, `bar-update`), from `bar-stats` (`stat`), or from `BarState.qml` (`value`), which reads state files with FileView/inotify, no process: alerts `~/.local/state/alerts/<kind>[.count]` (`bar-alert push|open`), drawer `$XDG_RUNTIME_DIR/bar-tray-open` (`bar-tray toggle`), timer `$XDG_RUNTIME_DIR/bar-timer` (`bar-timer click|add|expire`, counted down in QML); scripts only handle clicks. `apps/bar-stats` is the shell's only resident child (one thread asleep in poll()): it reads the fili-shell pipe for FiliShell.qml, writes CPU/RAM/temperature/disk/network/SSH/airplane/VPN/backup as `stat NAME JSON` (`BarScript { stat: "..." }`, no script), the charger as `ac 0|1` (kernel uevents, for FiliSound), rereads SSH/airplane/VPN/backup at once on `bar refresh 14|18|21|22`; low battery runs `bar-status batwatch`. Niri state comes straight from `$NIRI_SOCKET` (Quickshell `Socket`), no `niri msg` process. Measure with `tests/fili-shell/bench.sh`. Audio, MPRIS, Bluetooth, tray, keyboard layout, workspaces are native. New indicator: prefer `bar refresh N` over an `interval`; a fili-tooltip that needs fresh data uses `tipCmd` (run on hover only).
- Wallpaper: static `swaybg` via `~/.local/bin/wallpaper [image]`, images in `~/.local/share/wallpapers/`. Never animated.
- Visual changes follow `references/brand.md`; interface design (type scale, spacing, tokens, states, card and panel layout) follows the `filigrane-ui` skill.
