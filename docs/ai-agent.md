# AI agent

Filigrane ships with a helper that starts an AI coding agent on your machine. The agent can install packages, enable services, change settings and update the system, following the rules in `AGENTS.md` and the `filigrane` skill.

## Starting it

`Mod+Y` (or the menu › AI) runs `fili-ai`, which starts the chosen agent in its working directory (`~/work` by default, `FILI_AI_WORKDIR`). The repository path is exported as `FILIGRANE_DIR` and is writable by the agent.

```
fili-ai [prompt]          start the agent, optionally with a first prompt
fili-ai use [agent]       choose the agent (a list if omitted), installing it if needed
fili-ai pick              the same choice in a menu
fili-ai install <agent>   install or update one agent
fili-ai update            update every installed agent
fili-ai status            agent, model, working directory, repo, installed agents
```

## Agents

| Agent | Provider | Notes |
|---|---|---|
| `claude` | Anthropic, Claude Code | Default. Updates itself |
| `codex` | OpenAI, Codex CLI | Runs in a sandbox |
| `opencode` | Mistral, Gemini, OpenRouter, DeepSeek... | Asks before every shell command |
| `ollama` | Local models through Codex CLI | Nothing leaves the machine. Heavy: the default model `gpt-oss:20b` needs about 16 GB of RAM. With less, set `FILI_AI_MODEL=qwen3:8b` (about 6 GB). Ollama only runs while `fili-ai` does |
| `none` | | No agent |

Binaries live in `~/.local/opt/<agent>-<version>` and are linked in `~/.local/bin`. Models for Ollama live in `~/.ollama/models` (`ollama list`, `ollama rm <model>`).

## Choosing durably

`fili-ai use <agent>` only changes your local choice, stored in `~/.config/filigrane/ai.env`. That file is generated by `bootstrap.sh` from `config.env`, so to keep a choice across runs set it in your personal layer:

```
# users/<login>/config.env
FILI_AI="${FILI_AI:-codex}"
FILI_AI_MODEL="${FILI_AI_MODEL:-}"
FILI_AI_WORKDIR="${FILI_AI_WORKDIR:-Projects/filigrane}"
FILI_AI_ARGS="${FILI_AI_ARGS:-}"
```

`FILI_AI_ARGS` replaces the agent's default options (permissions, sandbox). Leave it empty unless you know what you want.

## Signing in

| Agent | Command |
|---|---|
| Claude Code | `/login` at first launch |
| Codex | `codex login` |
| opencode | `/connect` or `opencode auth login` |

Credentials stay in each agent's own files. The agent is told never to read or copy them, and the Claude Code and Codex permission rules deny it.

## What the agent knows

- **`AGENTS.md`** at the repo root: the hard rules (xbps, runit, layers, git, forbidden commands). `CLAUDE.md` only imports it, so all agents read the same text.
- **The `filigrane` skill** (`agents/skills/filigrane/`): linked into `~/.claude/skills` for Claude Code and `~/.agents/skills` for the others. It loads detail on demand: everyday tasks, system, niri, resources, visual identity.
- **`agents/work/`**: instructions linked into the working directory, so an agent started in `~/work` knows the machine runs Filigrane and where the repo is.

## Safety

- Claude Code and Codex get passwordless `sudo` for `sv` and `xbps-*` only (`/etc/sudoers.d/zz-agent`, written by `bootstrap.sh` from `FILI_AI`). The confirmation comes from the agent instead: Claude Code's permissions plus the `~/.claude/hooks/guard-destructive.sh` hook, Codex's sandbox plus `~/.codex/rules/filigrane.rules`.
- opencode asks before every shell command (`~/.config/opencode/opencode.json`) and `sudo` keeps its password: the agent hands you the command to run.
- Switching to an agent that does not need it (or `none`) removes the sudo rule at the next `./bootstrap.sh --system-only`.
- Never allowed, whatever the agent: `mkfs`, `wipefs`, `parted`, `dd` on a disk, editing `/etc/sudoers*` or `~/.ssh`, reading credentials.
- The agent asks before system updates, `sv restart/stop`, `rm` outside the repo and its working directory, editing `/etc`, the bootloader and reboots.

## Resource rule

The OS must stay out of the way. Before installing something heavy (desktop environment, Electron, a Docker daemon, a JVM, a permanent indexer, a local LLM), the agent warns you and proposes a lighter alternative. After a durable install it measures the effect with `budget save before` and `budget diff before`.
